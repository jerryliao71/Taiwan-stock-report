# 台股財測評價台

<https://jerryliao71.github.io/Taiwan-stock-report/valuation/>

以 125 檔個股的 EPS 財測為輸入，用規則式模型推導每一檔的合理本益比、目標價區間與評等，
並標出與原表設定分歧、財測達成落後、數據異常之處。

**所有輸入都來自官方申報，沒有人工維護的數字，也沒有 AI 模型參與。**

## 前瞻 EPS 怎麼在沒有財測的情況下算出來

台灣沒有可用的官方前瞻財測（證交所 `t187ap15_L` 全市場僅 6 家公司），但每家公司都必須申報
**季度財報**與**每月營收**，兩者合起來就能定出前瞻 EPS：

```
股數   = 稅後淨利 ÷ 基本EPS
淨利率 = 稅後淨利 ÷ 營業收入
前瞻EPS = 前瞻營收 × 淨利率 ÷ 股數
```

股數相消後化簡為：

```
全年EPS  = 累計至第Q季EPS × ( 預估全年營收 ÷ 同期間營收 )
基準年EPS = 全年EPS × ( 1 + 阻尼後的營收年增率 )
```

已過月份的營收是**公布數字不是估計**，只有剩餘月份採最近兩個月平均當執行率。
營收年增率超過 20% 的部分只採計 35%、上限 40%。

驗證：與人工財測比對，台積電 −4%、鴻海 −6%、國巨 −4%、智邦 +5%，中位數絕對差異 16%。

## 這裡的資料哪些會自動更新

| 欄位 | 來源 | 更新 |
| --- | --- | --- |
| 上市收盤價、漲跌幅 | 證交所 `exchangeReport/STOCK_DAY_ALL` | 每交易日 |
| 上櫃收盤價 | 櫃買中心 `tpex_mainboard_quotes` | 每交易日 |
| 興櫃參考價 | 櫃買中心 `tpex_esb_latest_statistics` | 每交易日 |
| 官方本益比／股價淨值比／殖利率 | 證交所 `BWIBBU_ALL`、櫃買 `tpex_mainboard_peratio_analysis` | 每交易日 |
| 累計 EPS、營收、稅後淨利 | 公開資訊觀測站 `t187ap14_L`、`mopsfin_t187ap14_O` | 每季 |
| 每月營收、年增率 | 公開資訊觀測站 `t187ap05_L`、`mopsfin_t187ap05_O` | 每月 10 日前 |

125 檔中 **117 檔可完全自動推算**。其餘 8 檔（KY 外國企業與興櫃公司）的財報不在官方
opendata 內，改用 `data/forecasts.json` 的人工財測，並在頁面該列標示來源。

## 人工校正 data/overrides.json

官方推算看不到法說會指引、新產能、一次性損益與產品組合變化。需要覆寫時編輯
[`data/overrides.json`](data/overrides.json)，**這一層永遠優先於官方推算，排程不會覆寫它**。

```jsonc
"2454": {
  "eps": 155.4,              // 直接指定基準年 EPS
  "eps_year": 2027,
  "reason": "法說會指引旗艦晶片 2027 放量，營收動能推算未能反映",
  "date": "2026-08-26",
  "expires": "2026-11-30"    // 到期後自動失效，改回官方推算
}
```

可覆寫 `eps` / `eps_year` / `anchor`（產業基準倍數）/ `pe_mid`（直接指定合理本益比，跳過所有係數）/
`sector` / `exclude`。每筆都必須有 `reason` 與 `date`。

`expires` 是刻意的設計——手動判斷會過時，而官方數字每天在更新。過期的校正會在頁面標示為已失效。
被校正的個股在表格左緣是黃銅色標記，並在「人工校正」區塊列出理由與被取代的原始推算值。

## 參數校準

產業基準倍數與各項係數**每季重新校準一次**，由排程任務
`quarterly-valuation-recalibration` 於 **4／6／9／12 月 15 日 20:00** 執行，
時點落在台灣財報申報截止日（3/31、5/15、8/14、11/14）之後兩週以上。校準結果開 PR，不直接上線。

兩次校準之間的健康指標是**全市場校準常數 k**，每次建置自動重算並顯示在頁首：

| k | 意義 |
| --- | --- |
| 0.92 ~ 1.10 | 基準表與市場一致 |
| 0.85 ~ 0.92 或 1.10 ~ 1.20 | 開始偏離，下次校準時留意 |
| 超出 0.85 ~ 1.20 | 基準表跟不上市場，建議提前校準 |

歷次校準紀錄見 `CALIBRATION.md`。

## data/forecasts.json 的角色

它**不再參與估值**，只做兩件事：

1. 提供標的清單（125 檔的代碼、名稱、族群、市場別）
2. 「vs 人工財測」欄位的對照基準

不更新它也不會讓估值失真——估值只看官方數字。

每檔的欄位：

```jsonc
{
  "code": "2330", "name": "台積電", "market": "上市",
  "sector": "晶圓代工",          // 影響模型採用的產業基準倍數
  "eps":     { "2024": 45.25, "2025": 66.20, "2026": 109.80, "2027": 148.60 },
  "eps_old": { "2026": 61.80, "2027": 130.00 },   // 舊財測，用於計算上修下修動能
  "pe_band": [15, 25],           // 原表人工設定的本益比區間，僅作對照
  "updated": "2026-07-18"        // 財測更新日，逾 190 天會標記為過舊
}
```

## 本機執行

```bash
npm run build:valuation      # 抓官方資料 → 跑模型 → 產生 valuation/dist/index.html
```

不需要 pip 安裝，只用 Python 標準函式庫。

## 檔案

- `pipeline/fetch_official.py` — 抓取七個官方端點，各自保留資料日期
- `pipeline/model.py` — 評價模型（產業基準、成長、財測修正、品質、市場回歸、全市場校準）
- `pipeline/build.py` — 串接並產生靜態頁
- `pipeline/fetchlib.py` — 具重試與 TLS 相容處理的抓取工具
- `templates/` — 頁面模板，`__DATA__` / `__META__` / `__PRICE_DATE__` 於建置時填入
- `data/forecasts.json` — 人工維護的財測輸入

## 已知限制

- 模型是橫斷面規則框架，不是逐家公司的基本面研究，也不是券商共識或目標價。
- 完全承接 `forecasts.json` 的財測；財測錯，結論就跟著錯。目前有 8 檔被自動標記為數據待確認。
- 刻意納入市價作為 25% 的先驗，因此在判斷「市場整體是否錯價」上必然偏保守。
- 未納入資產負債表、現金流、股利、股本變動與流動性。
- KY 外國企業與興櫃公司的綜合損益表不在官方 opendata 內，共 8 檔沒有實績可對照。

## TLS 備註

櫃買中心部分主機的憑證缺少 Subject Key Identifier 擴充，Python 3.13+ 預設的
`VERIFY_X509_STRICT` 會拒絕連線，且該行為在其負載平衡的主機間不一致。
`fetchlib.py` 會在嚴格模式失敗後改用非嚴格模式重試——**仍然驗證憑證鏈與主機名稱**，只是不要求該擴充欄位。
